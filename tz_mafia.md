# ТЗ: AI Mafia — Браузерная игра в мафию с ИИ-агентами

## 1. Общее описание проекта

**AI Mafia** — веб-приложение, в котором ИИ-агенты играют друг с другом в классическую мафию. Пользователь выступает в роли наблюдателя: настраивает игроков, выбирает модели, запускает игру и смотрит, как ИИ-агенты обсуждают, обвиняют, защищаются и голосуют. Каждый игрок может быть подключён к разной LLM-модели через OpenRouter. Все игры записываются, ведётся статистика.

## 2. Основные сущности

### 2.1. Игрок (Player)

Каждый игрок — это ИИ-агент с настраиваемым профилем.

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | string (uuid) | Уникальный идентификатор |
| `name` | string | Имя персонажа (например, «Виктор», «Шерлок», «Патрик») |
| `avatar` | string (URL / base64) | Фотография / картинка, отображается в кружке |
| `color` | string (hex) | Уникальный цвет игрока (для чат-лога и подсветки) |
| `systemPrompt` | string | Персональный промпт — описание характера, стиля речи, манеры поведения. Примеры: «Ты параноидальный детектив, подозреваешь всех», «Ты добродушный простак, легко веришь другим» |
| `modelId` | string | Идентификатор модели на OpenRouter (например, `anthropic/claude-sonnet-4-20250514`, `openai/gpt-4o`, `google/gemini-2.0-flash`) |
| `ttsVoiceId` | string \| null | (Будущее) ID голоса для TTS-провайдера |
| `ttsEnabled` | boolean | (Будущее) Включена ли озвучка для этого игрока |

Игроки сохраняются в **библиотеку игроков** (localStorage → в будущем БД). Перед началом игры пользователь выбирает из библиотеки 6–12 игроков для текущей партии.

### 2.2. Игровая роль (Role)

Классические роли мафии:

| Роль | Сторона | Ночное действие | Описание |
|------|---------|----------------|----------|
| **Мирный житель** | Город | Нет | Обычный горожанин, голосует днём |
| **Мафия** | Мафия | Выбирает жертву (совместно с другими мафиози) | Знает других мафиози |
| **Комиссар** (Шериф) | Город | Проверяет одного игрока (мафия/не мафия) | Получает результат проверки |
| **Доктор** | Город | Защищает одного игрока от убийства | Не может защитить себя два раза подряд |

**Распределение ролей по умолчанию (настраиваемое):**

| Кол-во игроков | Мафия | Комиссар | Доктор | Мирные |
|---------------|-------|----------|--------|--------|
| 6 | 2 | 1 | 1 | 2 |
| 7 | 2 | 1 | 1 | 3 |
| 8 | 2 | 1 | 1 | 4 |
| 9 | 3 | 1 | 1 | 4 |
| 10 | 3 | 1 | 1 | 5 |
| 11 | 3 | 1 | 1 | 6 |
| 12 | 4 | 1 | 1 | 6 |

Пользователь может переопределить количество ролей вручную через настройки перед игрой.

### 2.3. Правила игры (GameRules)

Правила описываются в текстовом формате и передаются каждому агенту как часть system prompt. По умолчанию заполнены стандартными правилами мафии, но пользователь может редактировать их в отдельном меню настроек.

```
{
  "rulesText": "Ты играешь в мафию. Правила: ... (полный текст правил)",
  "maxSpeechesPerDay": 1,           // Сколько раз игрок может высказаться в фазе обсуждения
  "discussionRounds": 2,            // Сколько кругов обсуждения перед голосованием
  "allowLastWords": true,           // Последнее слово перед «казнью»
  "revealRoleOnDeath": true,        // Показывать роль убитого/казнённого
  "firstNightKill": false,          // Убийство в первую ночь
  "doctorSelfHealLimit": 1          // Сколько раз доктор может лечить себя за игру
}
```

### 3.3. Важно: API-ключи

Поскольку приложение клиентское (без бэкенда на первом этапе), API-ключ OpenRouter вводится пользователем в настройках и хранится в `localStorage`. Все запросы к OpenRouter идут напрямую из браузера. Это безопасно для личного использования, но не для публичного деплоя с общим ключом.

Настройки API:

```
{
  "openRouterApiKey": "sk-or-...",
  "openRouterBaseUrl": "https://openrouter.ai/api/v1",
  "defaultModel": "anthropic/claude-sonnet-4-20250514",
  "ttsProvider": null,             // "elevenlabs" | "openai" | null
  "ttsApiKey": null,
  "maxTokensPerReply": 300,        // Ограничение длины реплики ИИ
  "temperature": 0.9               // Креативность по умолчанию
}
```

## 4. Игровой движок (Game Engine)

### 4.1. Состояния игры (State Machine)

```
LOBBY → ROLE_ASSIGNMENT → NIGHT_PHASE → DAY_ANNOUNCEMENT → 
DAY_DISCUSSION → DAY_VOTING → VOTE_RESULT → 
[LAST_WORDS →] CHECK_WIN → NIGHT_PHASE (цикл)
                                        ↓
                                    GAME_OVER
```

**Подробное описание каждого состояния:**

#### LOBBY
- Пользователь выбирает игроков из библиотеки (6–12)
- Настраивает правила, распределение ролей
- Нажимает «Начать игру»

#### ROLE_ASSIGNMENT
- Система случайным образом распределяет роли
- Каждому ИИ-агенту в system prompt добавляется информация о его роли
- Мафиози получают информацию о том, кто ещё мафия
- На экране: анимация раздачи карт / показ ролей наблюдателю (пользователь видит все роли)

#### NIGHT_PHASE
Ночью действуют только специальные роли. Порядок действий:

1. **Мафия совещается** — генерируется внутренний диалог мафиози (2–4 реплики между собой), после чего они выбирают жертву. В чат-логе отображается как скрытый/тёмный блок (если пользователь хочет, может раскрыть).
2. **Комиссар проверяет** — выбирает одного живого игрока для проверки. Получает ответ: «мафия» или «не мафия». Реализуется как один вызов LLM с просьбой выбрать цель проверки.
3. **Доктор лечит** — выбирает одного живого игрока для защиты. Реализуется аналогично комиссару.

Все ночные действия происходят «параллельно» (не видят решения друг друга). Результат рассчитывается после завершения всех действий.

**Логика разрешения ночи:**
```
если доктор защитил жертву мафии → никто не умирает
иначе → жертва мафии погибает
```

#### DAY_ANNOUNCEMENT
- Ведущий (система) объявляет результаты ночи
- «Город просыпается. Этой ночью был убит [имя] — он/она был(а) [роль, если revealRoleOnDeath]»
- Или: «Город просыпается. Этой ночью никто не пострадал.»
- Анимация: убитый игрок «гаснет» на столе (серый фильтр, перечёркнутый)

#### DAY_DISCUSSION
Это ключевая фаза — здесь происходит основной диалог.

**Механика обсуждения:**

1. Система определяет **порядок выступлений** (случайный или по кругу).
2. Каждый живой игрок по очереди получает контекст и высказывается.
3. После круга выступлений возможен второй круг (настраивается).

**Промпт для каждого игрока на этапе обсуждения:**

```
[System prompt игрока — характер, стиль]
[Правила игры]
[Твоя роль: ...]
[Если мафия: «Твои союзники: ...»]
[Если комиссар: «Результаты твоих проверок: ...»]

Сейчас идёт день {N}. Обсуждение.
Живые игроки: [список]
Убитые/казнённые ранее: [список с ролями, если раскрываются]

Лог обсуждения на сегодня:
- Виктор: «Я думаю, что Патрик подозрительно молчал вчера...»
- Шерлок: «Согласен, но меня больше беспокоит Анна...»

Твоя очередь высказаться. Говори кратко (2–4 предложения). 
Ты можешь: обвинять, защищаться, делиться подозрениями, блефовать.
Помни свою роль и действуй в интересах своей стороны.

Ответь ТОЛЬКО своей репликой от первого лица, без пояснений.
```

**Важно:** каждый игрок получает ТОЛЬКО ту информацию, которую он должен знать по правилам. Мирный не знает, кто мафия. Мафия не знает, кого проверил комиссар. И т.д.

#### DAY_VOTING
После обсуждения — голосование за «казнь».

1. Каждый живой игрок по очереди получает промпт с просьбой проголосовать.
2. Промпт содержит лог обсуждения и просьбу назвать имя подозреваемого (или «пропустить»).
3. Голоса подсчитываются. При равенстве — повторное голосование или никто не казнён (настраивается).

**Промпт для голосования:**
```
Голосование. На основе обсуждения, за кого ты голосуешь?
Живые игроки: [список, кроме тебя]
Ответь JSON: {"vote": "имя_игрока"} или {"vote": "skip"}
```

#### VOTE_RESULT
- Подсчёт голосов
- Объявление результата: «Большинством голосов казнён [имя]. Он/она был(а) [роль]»
- Анимация: игрок «выбывает» со стола

#### LAST_WORDS (опционально)
- Если включено в правилах, казнённый произносит последнее слово
- Один вызов LLM: «Тебя казнили. Скажи последнее слово.»

#### CHECK_WIN
Проверка условий победы:
- **Город побеждает**, если все мафиози казнены/убиты
- **Мафия побеждает**, если количество мафиози >= количество мирных
- Если никто не победил → переход к NIGHT_PHASE

#### GAME_OVER
- Объявление победителя
- Показ всех ролей
- Запись статистики в базу
- Кнопки: «Новая игра» / «Вернуться в лобби»

### 4.2. Формат данных состояния игры (GameState)

```typescript
interface GameState {

  };
```

## 5. LLM-интеграция (OpenRouter)

### 5.1. Абстрактный интерфейс

```typescript
interface LLMService {
  generateReply(params: {
    systemPrompt: string;
    messages: ChatMessage[];
    modelId: string;
    maxTokens: number;
    temperature: number;
    responseFormat?: 'text' | 'json';
  }): Promise<string>;
}

// OpenRouter реализация
class OpenRouterService implements LLMService {
  private apiKey: string;
  private baseUrl: string = 'https://openrouter.ai/api/v1/chat/completions';
  
  async generateReply(params) {
    const response = await fetch(this.baseUrl, {
      method: 'POST',
      headers: {
        'Authorization': `Bearer ${this.apiKey}`,
        'Content-Type': 'application/json',
        'HTTP-Referer': window.location.origin,
      },
      body: JSON.stringify({
        model: params.modelId,
        messages: [
          { role: 'system', content: params.systemPrompt },
          ...params.messages
        ],
        max_tokens: params.maxTokens,
        temperature: params.temperature,
      })
    });
    const data = await response.json();
    return data.choices[0].message.content;
  }
}
```

### 5.2. Построение промптов

Для каждого вызова LLM собирается промпт из нескольких частей:

```
SYSTEM PROMPT = 
  [Персональный промпт игрока (характер)] +
  [Правила игры] +
  [Роль и приватная информация] +
  [Инструкции для текущей фазы]

USER MESSAGE =
  [Контекст текущего дня/ночи] +
  [Лог обсуждения (то, что игрок слышал)] +
  [Конкретный запрос: «Выскажись» / «Проголосуй» / «Выбери цель»]
```

### 5.3. Форматы ответов

Для голосования и ночных действий используется JSON-формат:

```json
// Голосование
{"vote": "Виктор"}

// Ночное действие мафии
{"target": "Анна"}

// Ночное действие комиссара
{"investigate": "Патрик"}

// Ночное действие доктора
{"protect": "Шерлок"}
```

Для речи — свободный текст. Обрезается, если превышает `maxTokensPerReply`.

### 5.4. Обработка ошибок LLM

- Если модель вернула невалидный JSON → повторный запрос (до 3 попыток) с уточнением формата
- Если модель назвала несуществующего/мёртвого игрока → повторный запрос с указанием на ошибку
- Если API недоступен → пауза с уведомлением пользователя, кнопка «Повторить»
- Если модель пишет слишком длинную реплику → обрезка до maxTokens

## 6. TTS-интеграция (будущее)

### 6.1. Абстрактный интерфейс

Закладываем интерфейс сразу, реализуем позже:

```typescript
interface TTSService {
  synthesize(params: {
    text: string;
    voiceId: string;
    speed?: number;
    pitch?: number;
  }): Promise<AudioBuffer | Blob>;
  
  getAvailableVoices(): Promise<Voice[]>;
  
  isAvailable(): boolean;
}

interface TTSConfig {
  provider: 'elevenlabs' | 'openai' | 'browser' | null;
  apiKey: string | null;
  enabled: boolean;
  globalSpeed: number;        // 0.5 – 2.0
}
```

### 6.2. Точка интеграции

В Game Engine после генерации текстовой реплики:

```typescript
async function processLine(playerId: string, text: string) {
  // 1. Добавляем текст в чат-лог (сразу)
  addToLog(playerId, text);
  
  // 2. Если TTS включён — генерируем и проигрываем аудио
  if (ttsService.isAvailable() && player.ttsEnabled) {
    const audio = await ttsService.synthesize({
      text,
      voiceId: player.ttsVoiceId
    });
    await playAudio(audio);  // Ждём окончания воспроизведения
  } else {
    // Без TTS — показываем текст с эффектом печатания
    await typewriterEffect(text, estimatedReadingTime(text));
  }
  
  // 3. Переходим к следующему игроку
  nextTurn();
}
```

### 6.3. UI-элементы для TTS

- Глобальный переключатель TTS (вкл/выкл) в шапке
- Регулятор скорости речи
- Индикатор: иконка динамика рядом с аватаром говорящего игрока
- Возможность включить/выключить TTS для отдельного игрока

## 7. Интерфейс (UI/UX)

### 7.1. Основные экраны

#### Экран 1: Главное меню
- Кнопки: «Новая игра», «Библиотека игроков», «Статистика», «Настройки»

#### Экран 2: Библиотека игроков
- Список всех созданных игроков (карточки)
- Каждая карточка: аватар (кружок), имя, назначенная модель, кнопки «Редактировать» / «Удалить»
- Кнопка «Создать нового игрока» → модальное окно с формой:
  - Загрузка/вставка аватара (drag & drop или URL)
  - Имя
  - Цвет (color picker)
  - System prompt (textarea с подсказками)
  - Выбор модели (dropdown, модели подтягиваются с OpenRouter)
  - (Будущее) Выбор голоса TTS

#### Экран 3: Лобби (настройка игры)
- Слева: «стол» — овальная область, куда перетаскиваются игроки из библиотеки
- Справа: список доступных игроков из библиотеки
- Drag & drop или кнопка «Добавить за стол»
- Внизу: настройки игры:
  - Количество мафиози / комиссаров / докторов (или «авто» по таблице)
  - Кнопка «Редактировать правила» → модальное окно с textarea правил
  - Прочие параметры (количество кругов обсуждения, последнее слово и т.д.)
- Кнопка «Начать игру» (активна, если за столом 6–12 игроков)

#### Экран 4: Игровой экран (основной)

Разделён на две части:

**Левая часть (~65% ширины): Игровой стол**
- Овальный / круглый стол, вид сверху (2D)
- Игроки расположены по кругу — каждый в виде кружка с аватаром
- Подсветка говорящего: яркий цветной ореол (glow) вокруг аватара + мягкая пульсация
- Мёртвые игроки: серый фильтр (grayscale), полупрозрачность, значок ✗
- Фаза дня: светлый фон стола (тёплый)
- Фаза ночи: тёмный фон (синий/фиолетовый), спящие игроки «засыпают» (анимация закрытых глаз или zzz)
- В центре стола: текущая фаза и номер дня/ночи
- При голосовании: стрелки от голосующего к цели (с анимацией)

**Правая часть (~35% ширины): Чат-лог**
- Как в мессенджере: каждое сообщение — блок с:
  - Мини-аватар (кружок) слева
  - Имя игрока (в его цвете)
  - Текст реплики
  - Метка модели (мелким шрифтом, например «claude-sonnet-4-20250514»)
- Системные сообщения (ведущий): по центру, другой стиль (серый фон, без аватара)
  - «Наступает ночь...»
  - «Город просыпается. Убит Виктор.»
  - «Голосование: Патрик — 4 голоса, Анна — 2 голоса»
- Автоскролл вниз при новых сообщениях
- Кнопка прокрутки наверх

**Панель управления (внизу или сверху):**
- Кнопка «Пауза / Продолжить» — останавливает генерацию следующей реплики
- Кнопка «Ускорить» — убирает задержку между репликами, печатает мгновенно
- Кнопка «Следующий шаг» (в режиме паузы) — продвигает игру на одну реплику/действие
- (Будущее) Переключатель TTS: вкл/выкл + ползунок скорости
- Кнопка «Завершить игру досрочно»

#### Экран 5: Итоги игры
- Кто победил (город / мафия) — большой баннер
- Таблица всех игроков: имя, роль, статус (жив/казнён/убит, на каком раунде), модель
- Кнопки: «Играть снова (те же игроки)», «В лобби», «Статистика»

#### Экран 6: Статистика
- Таблица игроков с агрегированной статистикой
- Фильтры: по модели, по имени игрока, по дате

### 7.2. Анимации и визуальные эффекты

| Событие | Анимация |
|---------|----------|
| Игрок говорит | Цветной glow вокруг аватара (pulsating), остальные слегка затемнены |
| Голосование | Стрелка (линия) от голосующего к цели, появляется с анимацией |
| Казнь | Аватар уменьшается, становится серым, появляется ✗ |
| Убийство ночью | Аватар «гаснет» с эффектом fade-out → серый |
| Смена дня/ночи | Плавное изменение фона (day ↔ night gradient transition, ~1 сек) |
| Раздача ролей | Карточки «разлетаются» к игрокам (flip animation) |
| Новое сообщение в чате | Плавное появление (slide-in снизу) |
| Typewriter (когда TTS выключен) | Текст печатается посимвольно с курсором |

### 7.3. Адаптивность

- Desktop-first (основной сценарий — наблюдение за игрой)
- На мобильных: стол и чат-лог переключаются табами (стол / лог)
- Минимальная поддерживаемая ширина: 768px

## 8. Статистика и база данных

### 8.1. Что записываем

**После каждой игры (GameRecord):**

```typescript
interface GameRecord {
  id: string;
  startedAt: string;
  finishedAt: string;
  durationSeconds: number;
  totalDays: number;                    // Сколько дневных фаз прошло
  totalNights: number;
  winner: 'town' | 'mafia';
  playerCount: number;
  players: PlayerGameRecord[];
  fullLog: GameLogEntry[];              // Полный лог (для replay)
}

interface PlayerGameRecord {
  playerId: string;
  playerName: string;
  modelId: string;
  role: Role;
  survived: boolean;
  eliminatedAt: {                       // Когда выбыл
    phase: 'day_voting' | 'night_mafia';
    dayNumber: number;
  } | null;
  wasOnWinningSide: boolean;
  
  // Статистика активности
  totalSpeeches: number;                // Сколько раз высказывался
  totalVotesCast: number;               // Сколько раз голосовал
  votesReceivedAgainst: number;         // Сколько раз голосовали против него
  
  // Для специальных ролей
  correctInvestigations?: number;       // Комиссар: верных проверок
  totalInvestigations?: number;         // Комиссар: всего проверок  
  successfulHeals?: number;             // Доктор: успешных лечений
  totalHeals?: number;                  // Доктор: всего лечений
  mafiaKills?: number;                  // Мафия: участвовал в убийствах
}
```

### 8.2. Агрегированная статистика (PlayerStats)

Рассчитывается по всем играм конкретного игрока:

```typescript
interface PlayerStats {
  playerId: string;
  playerName: string;
  
  totalGames: number;
  wins: number;
  losses: number;
  winRate: number;                      // wins / totalGames * 100
  
  // Средняя выживаемость
  avgSurvivalDay: number;              // В среднем на каком дне выбывает
  survivalRate: number;                // % игр, где дожил до конца
  
  // По ролям
  roleStats: {
    [role: string]: {
      games: number;
      wins: number;
      winRate: number;
    }
  };
  
  // По моделям (если менялась модель)
  modelStats: {
    [modelId: string]: {
      games: number;
      wins: number;
      winRate: number;
    }
  };
  
  // Социальная статистика
  avgVotesReceivedPerGame: number;     // Насколько «подозрительный» игрок
  avgSpeechesPerGame: number;          // Насколько активный
}
```

### 8.3. Хранение

**Этап 1 (локальный):** IndexedDB через библиотеку `idb` (обёртка над IndexedDB с промисами).

Таблицы:
- `players` — библиотека игроков
- `games` — записи игр
- `playerGameRecords` — записи участия (для быстрой агрегации)

**Этап 2 (с бэкендом):** Миграция на Supabase (PostgreSQL) или SQLite через API-роут на Vercel.

## 11. Промпты по умолчанию

### 11.1. Правила игры (rules template)

```
Ты участвуешь в игре «Мафия». Вот правила:

СУТЬ ИГРЫ:
В городе живут мирные жители и мафия. Мафия пытается убить всех мирных, 
мирные пытаются вычислить и казнить всех мафиози.

ФАЗЫ:
- НОЧЬ: мафия выбирает жертву, комиссар проверяет одного игрока, доктор лечит одного игрока.
- ДЕНЬ: все обсуждают, кто может быть мафией, затем голосуют за казнь.

РОЛИ:
- Мирный житель: нет особых способностей, голосует днём.
- Мафия: ночью выбирает жертву. Знает других мафиози.
- Комиссар: ночью проверяет одного игрока (узнаёт, мафия или нет).
- Доктор: ночью защищает одного игрока от убийства.

ПОБЕДА:
- Город побеждает, если все мафиози казнены.
- Мафия побеждает, если мафиози >= мирных.

ВАЖНО:
- Отвечай КРАТКО (2–4 предложения в обсуждении).
- Играй в характере своего персонажа.
- Если ты мафия — скрывай это, обвиняй других, создавай алиби.
- Если ты мирный — анализируй поведение других, ищи противоречия.
- Не раскрывай свою роль напрямую (если только это не стратегический ход).
```

### 11.2. Примеры персональных промптов

```
// Параноик
"Ты подозрительный и нервный персонаж. Ты всех подозреваешь, часто меняешь мнение. 
Говоришь эмоционально, используешь восклицательные знаки. Склонен к теориям заговора."

// Аналитик
"Ты холодный, расчётливый аналитик. Ты основываешь свои выводы на логике и фактах. 
Ты запоминаешь, кто что говорил, и указываешь на противоречия. Говоришь спокойно и уверенно."

// Простак
"Ты добродушный и наивный. Ты легко веришь другим и часто соглашаешься с большинством. 
Иногда случайно говоришь подозрительные вещи, даже если невиновен. Говоришь просто, короткими фразами."

// Агрессор
"Ты агрессивный и напористый. Ты первым обвиняешь, давишь на других, требуешь ответов. 
Если кто-то обвиняет тебя — яростно защищаешься и переводишь стрелки."
```

## 12. Требования к качеству

- Код на TypeScript (strict mode)
- Компоненты — функциональные React-компоненты с хуками
- Минимальные зависимости (не тащить лишние библиотеки)
- Все LLM-вызовы — через абстрактный интерфейс (легко заменить провайдера)
- Все TTS-вызовы — через абстрактный интерфейс (заглушка на этапе 1)
- Весь текст интерфейса — на русском языке (код и комментарии — на английском)
- Анимации не должны блокировать UI (используем CSS transitions / Framer Motion)
- Поддержка тёмной темы (по желанию, но Tailwind упрощает)
